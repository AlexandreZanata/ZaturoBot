# 07 — Platform compliance and commercial permissions

Status: proposed design, not a production authorization. Official public documentation checked on 2026-11-14. No account was connected, credentials inspected, or publication attempted. Recheck platform evidence before each adapter is activated and after a policy-change alert.

## Decision and admission rule

A technically callable endpoint is insufficient. Admit an external action only when **all** of these hold: owner grant, eligible authenticated account, platform entitlement for that exact use, approved affiliate destination and link format, current product facts, content/disclosure checks, audience permission where relevant, available budget, and reconciliable operation state. Unknown evidence blocks external dispatch but permits an explicitly labeled local draft.

Store the evidence URL, retrieval date, applicable territory, account/medium scope, reviewed rule revision, and next review date with the policy record. Store a short conclusion and a digest rather than copying entire external terms. A model can flag a change; only the deterministic policy path can apply an owner-approved rule revision.

## Affiliate and source permission matrix

- **Shopee Brazil / approved public media / useful original product content / official affiliate link:** candidate for a later small MVP, subject to actual affiliate acceptance and medium approval. The official terms define registered approved affiliate media, a limited revocable right to display supplied links, public availability, and approval for social media. They prohibit modifying or deriving affiliate links or Shopee intellectual property without written consent. Do not build a custom link encoder or redirect cloak. These terms do not establish permission for arbitrary scraping. [Shopee affiliate terms](https://help.shopee.com.br/portal/10/article/124094-Programa-de-Afiliados-Shopee-Termos-e-Condi%C3%A7%C3%B5es).
- **Shopee Brazil / price and catalog ingestion / Affiliate Open API:** unverified account entitlement. The public [official Open API portal](https://affiliate.shopee.com.br/open_api) returned only its JavaScript application shell. No public schema, eligible-account proof, rate limit, retention policy, history license, or commission endpoint was verified. Use owner-imported facts obtained through authorized official tools for a draft MVP; retain provenance and an expiry. A real adapter waits for official documentation and an explicit account-specific grant. Third-party websites with similar names are not official API evidence.
- **Mercado Livre Brazil / approved public media / official links:** candidate only after current full terms are obtained and account eligibility is recorded. Official guidance describes the [affiliate link generator](https://www.mercadolivre.com.br/l/afiliados-gere-seus-links) and [starting recommendations](https://www.mercadolivre.com.br/l/comece-a-recomendar), but full term retrieval returned HTTP 403 at the [program terms](https://www.mercadolivre.com.br/ajuda/termos-condicoes-programa-afiliados-criadores_30228). Imported links must remain intact. A marketplace seller/catalog API does not prove affiliate API rights.
- **Mercado Livre / closed groups or offline distribution / affiliate links:** blocked pending authoritative clarification. The indexed official [sharing guidance](https://www.mercadolivre.com.br/l/afiliados-compartilhamento-de-publicacao) explicitly excludes offline media and closed groups, whereas broader official guidance mentions messaging channels. This conflict cannot be resolved by selecting the permissive excerpt. The complete sharing page also returned 403. Do not route these links into a closed Telegram or WhatsApp community.
- **Either marketplace / price history, commission tracking, mass catalog extraction:** planned and blocked until a licensed source or approved API/export is documented. Maintain separate observed price snapshots and merchant-confirmed conversions/commissions. An inferred sale, a click, or an estimated commission never becomes confirmed revenue.
- **Own educational site / original non-affiliate content / ordinary owned URLs:** simplest future publication surface after hosting and publication authorization. The operator controls content and scheduling, but this does not waive marketplace link restrictions, image rights, disclosure, or privacy rules. Start with non-affiliate useful content if affiliate onboarding is incomplete.

## Channel permission matrix

The draft/export path produces an asset package for a person to publish. It must never be reported as automated publication or as successful delivery.

- **Instagram:** local drafts are suitable now. Official API publishing targets professional accounts and requires the appropriate login/token and publishing permissions; media must be accessible to the API, and publishing status/limits must be checked. Production needs a permitted reviewed app/account configuration. [Instagram publishing documentation](https://developers.facebook.com/documentation/instagram-platform/content-publishing). Preserve MeuAssistente's decision against the Meta API: the proposed architecture does not activate an Instagram Meta route. Whether that decision also excludes a future Instagram-only API is an owner decision; until clarified, keep this adapter in draft/export mode.
- **TikTok:** use draft/export as the proposed default. Direct Post's current intended-use rules exclude private/internal utilities that only upload to the operator's or team's accounts. The required UX includes creator awareness, editable content, preview, privacy/commercial choices, and express upload consent. Unaudited clients are private-only with additional restrictions; an audit does not remove the intended-use rule. An unattended own-account agency must not be promised as eligible. A separately approved publishing service may be evaluated later without bypassing its consent requirements. [TikTok Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines), [Direct Post onboarding](https://developers.tiktok.com/docs/en/content-posting-api-get-started).
- **YouTube:** retain the existing YoutubeBot generation-only boundary. A future uploader needs OAuth permission such as `youtube.upload`, account eligibility, quota checks, explicit privacy settings, and separate owner publication authorization. Current insert documentation says unverified projects are **not** private-only and lists a separate Video Uploads bucket of 100 calls/day, one unit/call. Do not carry forward the older 1,600-unit/private-only assumptions. Verify the account's actual quotas before activation. [YouTube videos.insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert?hl=en). Commercial relationships require the applicable branded-content disclosure, and realistic meaningful generated/altered media requires disclosure where specified. [Branded content](https://support.google.com/youtube/answer/154235), [GenAI disclosure](https://support.google.com/youtube/answer/14328491).
- **Telegram:** best candidate for a small future official messaging publisher, subject to affiliate medium approval. A bot cannot initiate a user conversation: the user must first message it or add it to a group. Use an explicitly owned registered channel with only the necessary bot rights, or a consented user flow; never import or scrape contacts. [Telegram bots introduction](https://core.telegram.org/bots). Respect 429/backoff and conservative application limits; the FAQ currently advises roughly one message/second in one chat, 20/minute in a group, and about 30/second for free bulk notifications. Paid broadcasts remain disabled. [Telegram FAQ](https://core.telegram.org/bots/faq). Unsolicited spam is prohibited, and developers have data-protection responsibilities. [Bot developer terms](https://telegram.org/tos/bot-developers). API responses do not provide a general exactly-once send guarantee; lost acknowledgements require quarantine rather than a blind resend.
- **Pinterest:** useful for original educational/affiliate drafts; future production requires an eligible app, OAuth, needed scopes and Standard access. Trial-created Pins/Boards are creator-visible sandbox entities; a successful Trial response is not public publication. Credential/cookie capture is not the OAuth flow. [Pinterest access tiers](https://developer.pinterest.com/docs/key-concepts/access-tiers/). Its affiliate rules require transparency, original value, moderation, and avoidance of repetitive/high-volume manipulation; link behavior must be clear and some shorteners are unsupported. [Commercial and affiliate guidelines](https://policy.pinterest.com/en/commercial-and-branded-content-guidelines).
- **WhatsApp through MeuAssistente:** commercial production is blocked. Preserve its experimental fictitious-test restrictions, active profile/session, allowlists, pause controls, human takeover and no-Meta-API decision. No browser automation escalation, bulk outreach, new contact collection, or real commercial test is authorized here. The integration can supply synthetic verified facts through a mock channel while production eligibility remains unresolved.

## Disclosure, factual integrity and brand controls

The 2026 official Shopee guidance explicitly includes affiliate commissions in advertising disclosure and identifies responsibility for AI-assisted claims. [Shopee's CONAR 2026 guidance](https://help.shopee.com.br/portal/10/article/196794-Identifica%C3%A7%C3%A3o-de-Conte%C3%BAdo-Publicit%C3%A1rio%3A-Guia-CONAR-2026-para-Influenciadores-e-Afiliados). CONAR's [current guidance index](https://www.conar.org.br/diretrizes) links its [2026 influencer guide](https://conar.wpenginepowered.com/wp-content/uploads/2026/05/260525_GUIA_INFLUENCIADORES_CONAR_v6.pdf). Implementation should use the current full guide for a legal review before production.

Proposed product requirements:

- Render a conspicuous `pt-BR` advertising/affiliate notice before truncation or link activation, with channel-specific disclosure fields where required. A brand template may not hide or remove it.
- Reject claims of physical testing without a recorded actual test. Identify synthesized demonstrations and distinguish merchant specifications from observed facts.
- Every quoted price carries currency, variant, source, observation time, validity window, conditions, freight/tax caveats where applicable, and a revalidation rule. No invented crossed-out price, discount percentage, scarcity, or historical low.
- Only use owned/licensed media with an asset-rights record. Visual identity assets may not impersonate a marketplace or imply an endorsement. Platform-specific overlays and watermarks remain policy-controlled; a universal brand overlay is unsuitable for TikTok's API rules.
- Campaign approval references immutable content and brand revisions. Changing a material claim invalidates prior supervised approval.

## Privacy and audience requirements

A commercial agency is not automatically covered by the LGPD exclusion for exclusively personal, non-economic activity. LGPD sets processing principles, lawful-basis and consent requirements, security duties, and data-subject rights. [Current consolidated LGPD from Câmara dos Deputados](https://www2.camara.leg.br/legin/fed/lei/2018/lei-13709-14-agosto-2018-787077-normaatualizada-pl.html).

Proposed controls are deliberately concrete: record purpose, notice revision, channel, subject pseudonymous reference, consent or other documented lawful basis, timestamp and revocation; no marketing permission inferred from possession of a phone number. Opt-out blocks new queued-send admission at the authoritative endpoint immediately; global stop effectiveness requires affected executor acknowledgments, and already admitted calls may remain uncertain. Human takeover blocks automation for the claimed conversation. Define retention and a deletion workflow before ingestion; use aggregate metrics where possible and avoid individual behavioral profiles in the MVP. International provider transfers need a separate documented assessment. Do not send audience identifiers, messages, credentials, screenshots or account cookies to commerce model prompts by default.

## Verification and production gates

Dependencies: [repository audit](01-REPOSITORY-AUDIT.md), [contracts](04-INTEGRATION-CONTRACTS.md), [policy matrix](06-AUTONOMY-AND-POLICY-MATRIX.md), and [provider strategy](08-AI-PROVIDER-AND-COST-STRATEGY.md).

Acceptance requires synthetic tests that prove rejection of a missing/expired medium approval, prohibited channel/link combination, stale price, missing disclosure, revoked audience consent, unapproved model purpose, duplicate command and ambiguous send. An official sandbox verifies transport behavior only. Later production acceptance is a separately authorized observation with a saved public post/message identifier, resolved state and budget settlement. Never describe a local mock or API sandbox as a real public commercial send.

The shortest permitted path remains conditional: draft useful owned content, obtain one affiliate/medium approval or omit affiliate links, then activate one explicitly granted owned site or Telegram channel. WhatsApp and unattended TikTok are not prerequisites for that MVP.
