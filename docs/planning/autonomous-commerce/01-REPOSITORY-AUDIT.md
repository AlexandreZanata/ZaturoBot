### Implemented reusable foundation

1. **Durable task engine.** `crates/core/src/lib.rs:39` defines ten states and legal transitions; `:95` defines exactly Diagnostic, AssistedDiagnostic and Service. `:114` NewTask enforces 4096-byte request text, 128-byte idempotency keys, attempts 1..3 and task timeout 1..300 seconds. `:242` Task carries stable IDs, operation identity, owner request, assignment, lease and results. These short foreground limits are intentional; media background jobs use an accepted service response and later observation. Commerce must not keep an editorial schedule or a long video render inside a 300-second task.
2. **Transactional coordination.** `crates/services/src/lib.rs:48` creation, `:78` registration, `:120` claims, `:190` starts, `:215` heartbeats, `:237`/`:257` typed completions, `:376` controls and `:402` recovery use the single Engine. Recover requeues with the same operation ID, not a new identity. Existing recovery wording describes safe diagnostic retries; new external-effect executors must independently fence unsafe replay.
3. **Separated SQLite ownership.** `crates/db/src/repository.rs:20` opens hub schema **7**; `crates/db/src/journal.rs:12` opens worker schema **8**. `crates/db/src/lib.rs:36` configures WAL, foreign keys, FULL synchronous, 2-second busy handling, 2 MiB cache, transactional additive upgrade streams. Hub accepted old versions are 1/4/5; worker 2/3/6. Migrations 0001..0008 belong to distinct streams, not one database. SQL stays in db. Do not reserve the next migration number until concurrent work is reconciled.
4. **Worker operation journals.** `crates/db/src/journal.rs:31` begins an intent, `:63` records a matching diagnostic result, `:113`/`:145` handle assisted outcomes. `crates/db/src/service_journal.rs:20` returns Execute, Cached or Reconcile from durable service identity/request binding. Cached evidence can be resent; an unresolved side-effecting request becomes Reconcile. `apps/zaturo-worker/src/service_execution.rs:45` validates lease, deadline, service kind, exact capability, records intent, reconciles or executes fixed transport, validates and caches result before reporting. This is the closest commerce operation pattern.
5. **Private authenticated transport.** `apps/zaturo-hub/src/http.rs:16` exposes owner-authenticated `/v1/tasks`, task details/events/pause/resume/cancel and workers; body cap is the protocol cap. `/healthz` returns health/protocol without auth, containing no owner data; control APIs require auth. `/v1/worker` is independently authenticated WebSocket. `apps/zaturo-hub/src/clients.rs:15` defines separate application credentials and coarse submit/viewer scopes; `:27` validates private digest-only registry files with an eight-app bound. `crates/security/src/lib.rs:45` keeps SHA-256 digests, verifies constant-time and redacts Debug. Tagged ClientMessage/ServerMessage deny unknown fields/variants; service completions already exist.
