# Bounded assisted diagnostics

Own the two-step structured planning loop and acceptance of actual diagnostic evidence.
The model proposes; `zaturo-security` and the typed executor boundary authorize work.
There is one possible tool and no shell, file, network, or credential tool. Provider
transport and durable reservations belong to `zaturo-llm` and the worker's DB adapter.

The canonical prompt/schema are under `prompts/`; unknown fields, proposed tools,
repeated tools, and premature final answers fail closed. Owner requests and observations
are untrusted JSON message data, never system instruction substitutions. Do not persist
private reasoning. Always require a successful real `DiagnosticResult`, plus a concise
bounded final answer, before producing a successful orchestration report.

`cargo test -p zaturo-orchestrator` uses only fake model/executor/budget fixtures. Include
denial, malformed-output, cancellation, and invented-success regressions in changes.
